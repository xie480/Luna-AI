# Luna 日志、监控与审计方案设计文档

## 1. 章节目标

本文档旨在为 Luna 桌面 AI 助理设计一套符合本地化部署要求的全链路日志、监控与审计系统。明确从 Electron 前端发起、Python Backend 调度到 LLM 调用、工具执行的各环节如何实现请求追溯、任务状态监控、工具调用审计以及异常捕获，确保系统具备"高可观测性"和"问题定位能力"，同时兼顾本地机器的性能开销。

## 2. 设计背景与问题定义

Luna 是一个前后端分离的本地 AI 桌面助理架构（Electron -> Python Backend）。在这样的架构中，一个用户意图（例如"帮我总结一下昨天的会议纪要"）会触发跨模块的协作流程，涉及多 Agent 的路由、RAG 检索、LLM 调用以及本地 MCP 工具执行。

**面临的核心问题：**

1. **链路割裂**：一旦出现执行异常（如意图理解错误或工具执行超时），如果不进行跨层追踪，很难定位问题出在前端、调度引擎还是 LLM 推理侧。
2. **本地环境限制**：传统云原生的 ELK、Prometheus + Grafana 方案过于沉重，无法打包给普通桌面用户。
3. **审计合规与安全**：Agent 具有主动行为能力，执行了哪些高危工具（如删除文件、发送邮件）必须做到 100% 记录和防抵赖，以建立信任。
4. **长周期任务监控**：后台挂起的异步监控任务需要有明确的指标反映系统健康度，避免无声崩溃。

## 3. 核心设计思路

基于项目背景与限制，本方案遵循以下原则：

* **统一 Trace 体系，Python 侧汇聚**：通过生成全局唯一的 `TraceID` 串联前后端。Python 作为核心控制面，负责所有审计日志和状态指标的汇聚与本地落盘。
* **轻量级本地化存储**：
  * **常规流日志**：采用本地文件系统轮转（File Rotation），记录详细的 Debug/Info 信息。
  * **审计与业务日志**：采用 PostgreSQL 的专用 `audit_logs` 和 `trace_spans` 表存储结构化数据，支持前端面板查询。
* **分级降维**：对普通会话日志和底层工具执行日志进行隔离，工具执行必须强制审计并落地。
* **敏感数据脱敏**：AI 请求、用户隐私上下文在落盘时必须执行清洗过滤策略，防止本地权限越界。
* **开发者扩展性**：在调试模式下，支持将数据导出为标准的 OpenTelemetry (OTLP) 格式，供开发者外挂 Jaeger 等追踪工具。

## 4. 模块职责与边界

### 4.1 Electron 层 (UI & State)

* **职责**：拦截用户行为操作，在 WebSocket/SSE 请求 Python Backend 时附带或继承 `TraceID`；捕获前端渲染报错（Live2D崩溃、TTS播放失败等）并上报给 Python 端；内置"诊断面板"渲染。
* **禁止**：严禁前端直接读写 PostgreSQL 日志库；严禁前端绕过 Python 直接调用 LLM。

### 4.2 Python Backend 层 (Orchestration & Storage)

* **职责**：生成和传递贯穿全局的 `TraceID`；负责将各 Node/Agent/Workflow 的状态转移记录成结构化事件；持久化 LLM 推理日志和审计日志；核心 MCP Tool 调用的安全审计记录落地；暴露 WebSocket/HTTP 接口供前端"监控面板"查询日志与指标。
* **工具**：采用 Python `logging` 结构化 JSON 日志，结合 PostgreSQL 审计表持久化。

### 4.3 前端监控面板

* **职责**：通过 WebSocket/SSE 接收 Python 推送的实时状态事件；提供按 TraceID 查询的链路追踪视图；展示系统的关键 Metrics 图表（LLM 延迟、Token 消耗、工具调用频率等）。

## 5. 核心数据结构

*(假设：所有审计数据库表都存在于 Luna 本地的 PostgreSQL 中)*

### 5.1 Trace Span 表 (luna_telemetry schema)

```sql
CREATE TABLE trace_spans (
    span_id VARCHAR(64) PRIMARY KEY,       -- 雪花算法 ID
    trace_id VARCHAR(64) NOT NULL,          -- 全局 TraceID（雪花算法）
    parent_span_id VARCHAR(64),              -- 父 Span ID
    span_name VARCHAR(128) NOT NULL,         -- LLM_INVOKE, TOOL_CALL, STATE_TRANSITION...
    service_name VARCHAR(32) DEFAULT 'python-backend',
    start_time TIMESTAMPTZ NOT NULL,
    end_time TIMESTAMPTZ,
    duration_ms INT,
    status VARCHAR(16) DEFAULT 'OK',         -- OK, ERROR, TIMEOUT
    metadata JSONB,                          -- 结构化元数据
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_trace_spans_trace_id ON trace_spans(trace_id);
```

### 5.2 审计日志表

```sql
CREATE TABLE audit_logs (
    log_id VARCHAR(64) PRIMARY KEY,
    trace_id VARCHAR(64) NOT NULL,
    session_id VARCHAR(64),
    event_type VARCHAR(32) NOT NULL,     -- TOOL_EXECUTION, CONFIG_CHANGE, MEMORY_WRITE
    event_detail JSONB NOT NULL,
    severity VARCHAR(16) DEFAULT 'INFO', -- INFO, WARN, ERROR
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 6. TraceID 生命周期

1. **Python API 入口**：Electron 发起请求时，WebSocket/SSE 消息携带可选 TraceID；若未携带，Python 入口生成新的 TraceID（雪花算法）。
2. **日志绑定**：Python 使用 `contextvars` 将 TraceID 绑定到当前 asyncio Task，所有日志自动携带。
3. **跨模块传递**：在 Memory、LLM、Tool 各模块调用时，TraceID 通过上下文参数显式传递。
4. **Electron 透传**：前端在 WebSocket 连接建立时获取初始 TraceID，后续请求自动复用。

## 7. Metrics 收集

Python Backend 内置轻量级 Metrics 收集：

| 指标                            | 类型      | 说明                       |
|:------------------------------|:--------|:-------------------------|
| `http_request_duration_ms`    | Histogram | API 请求耗时分布               |
| `llm_invoke_latency_ms`       | Histogram | 大模型调用延迟                 |
| `llm_ttft_ms`                 | Gauge     | 流式接口首字延迟               |
| `tool_execution_duration_ms`  | Histogram | 工具执行耗时                  |
| `memory_extraction_latency_ms`| Histogram | 记忆提取延迟                  |

## 8. 敏感数据脱敏

所有日志输出前必须经过以下过滤规则：

1. **API Key 正则**：匹配 `sk-` 开头的字符串，替换为 `[REDACTED_API_KEY]`
2. **密码/Token 字段**：匹配 `password`、`token`、`secret` 等字段的值，替换为 `[REDACTED]`
3. **用户敏感信息**：可配置 Regex 规则，如手机号、邮箱脱敏

## 9. 落地实施建议

1. **Phase 1**：实现 Python 基础结构日志（TraceID + 文件轮转）。
2. **Phase 2**：实现审计日志表持久化和 Metrics 收集。
3. **Phase 3**：实现 Electron 调试面板，支持 TraceID 查询和链路可视化。
