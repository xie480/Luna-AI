# Luna 数据存储与同步方案

## 1. 章节目标

本文档定义 Luna 桌面 AI 助理中所有数据的持久化策略、存储引擎选型、跨层同步机制以及数据一致性保障方案。涵盖 PostgreSQL、Redis、Qdrant 三者的角色划分与协同。

## 2. 存储架构概览

│  │ Manager  │ │ Manager  │ │ Checkpointer│ │

## 3. 存储引擎职责

| 引擎        | 存储内容                                         | 读写模式             | 数据一致性要求     |
|:----------|:---------------------------------------------|:-----------------|:-------------|
| PostgreSQL | 长期记忆、用户配置、Prompt 模板、审计日志、会话元数据、LangGraph 检查点快照 | 事务性读写，高频读低频写    | 强一致（ACID）     |
| Redis     | 工作记忆（短期会话）、LangGraph 状态缓存、分布式锁、Event Bus 消息队列   | 高性能读写，毫秒级延迟     | 最终一致即可       |
| Qdrant    | 长期记忆向量索引、RAG 文档切片 Embedding                | 向量检索 + 异步写入     | 最终一致（允许写入延迟） |

## 4. Python 数据层架构

Python 端统一通过 Repository 模式访问各存储引擎：

```python
from abc import ABC, abstractmethod

class BaseRepository(ABC):
    @abstractmethod
    async def connect(self):
        """建立连接"""
        ...

    @abstractmethod
    async def disconnect(self):
        """关闭连接"""
        ...

class MemoryRepository(BaseRepository):
    """记忆数据仓库 - 操作 PostgreSQL + Qdrant"""
    ...

class SessionRepository(BaseRepository):
    """会话数据仓库 - 操作 Redis"""
    ...

class ConfigRepository(BaseRepository):
    """配置数据仓库 - 操作 PostgreSQL"""
    ...
```

## 5. 数据同步策略

### 5.1 记忆写入的一致性保障

Python 的 Memory Manager 在写入长期记忆时，采用**两阶段提交**模式：

1. **先写 PostgreSQL**：插入/更新事实记录，获取数据库生成的 ID。
2. **再写 Qdrant**：使用同一 ID 写入向量索引。
3. **异常回滚**：如果 Qdrant 写入失败，回滚 PostgreSQL 事务。

### 5.2 Redis 缓存淘汰策略

- 工作记忆采用 **LRU 淘汰** + 会话 TTL（默认 24h）。
- LangGraph 检查点状态采用 **TTL 自动过期**（线程完成后 1h 自动清理）。
- 分布式锁采用 **Redlock 算法** 防止脑裂。

## 6. 数据库 Schema 概览

### 6.1 PostgreSQL 核心表

```sql
-- 长期记忆
CREATE TABLE long_term_memory (
    id VARCHAR(64) PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    domain VARCHAR(20) NOT NULL,
    memory_type VARCHAR(20) NOT NULL,
    content TEXT NOT NULL,
    confidence FLOAT DEFAULT 1.0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 配置版本历史
CREATE TABLE config_revisions (
    revision_id VARCHAR(64) PRIMARY KEY,
    config_key VARCHAR(128) NOT NULL,
    config_value TEXT NOT NULL,
    changed_by VARCHAR(64),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 审计日志
CREATE TABLE audit_logs (
    log_id VARCHAR(64) PRIMARY KEY,
    trace_id VARCHAR(64),
    event_type VARCHAR(32),
    event_detail JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.2 Redis Key 设计

```
luna:mem:chat:{session_id}:history   -> List (短期会话)
luna:mem:task:{plan_id}:working      -> Hash (任务工作记忆)
luna:state:langgraph:{thread_id}     -> String/JSON (LangGraph 状态)
luna:lock:{resource_id}              -> String (分布式锁)
luna:event:bus                       -> Pub/Sub (Event Bus)
```

### 6.3 Qdrant Collection 设计

```
collection: long_term_memory
  - vector_size: 1536 (默认 Embedding 维度)
  - distance: Cosine
  - payload: { id, content, domain, memory_type, confidence, created_at }
```

## 7. 落地实施建议

1. **Phase 1**：实现 PostgreSQL 基础表结构 + Redis 会话缓存。
2. **Phase 2**：接入 Qdrant 向量库，打通 Embedding 检索链路。
3. **Phase 3**：完善分布式锁和一致性保障机制。
